= Models

See https://ollama.com/library for the full library of open source LLMs that can be used with Ollama.

Popular models include Llama, Qwen, and DeepSeek. But there are lots of variations of these, and you will want to choose one that is going to run well on your particular hardware.

If you want the least risk and the easiest setup, start with a 3-8B model on a local machine with 16-32GB RAM.

.Recommended starter models
****
* *Llama 3.2 3B* (`ollama run llama3.2:3b`): A reliable general-purpose model that is easy to run on most modern desktops.
* *Mistral 7B* (`ollama run mistral`): A strong performer for both chat and coding while still being manageable on 16GB+ systems.
* *Gemma 3 12B* (`ollama run gemma3:12b`): A good choice for users with 32GB RAM who want higher quality without the risk of 33B-scale issues.
****

== Troubleshooting large models

Very large models like DeepSeek Coder 33B require substantial system resources and can be sensitive to runtime compatibility. Ensure your host has 32GB+ RAM available, and confirm the Ollama container can see that memory:

[source,bash]
----
docker exec ollama free -h
----

You can make more memory available to a container by configuring `docker-compose.yml` with `mem_limit` and `mem_reservation` options. If you still encounter errors like "llama runner process has terminated", try these troubleshooting steps:

* If using Docker Desktop, make sure the engine is allocated enough RAM. Check this in *Settings* > *Resources* > *Memory*.

* Ensure the model is fully downloaded: `./run/ollama ls` should show the model with full size.

* Restart the container: `./run/stop` then `./run/start`.

* Check Docker logs for detailed errors: `docker logs ollama`

* Verify your CPU supports modern instruction sets such as AVX2 or AVX-512.

* If a quantized variant is available, use it to reduce memory requirements.

Some 33B models may still fail even when the container has enough memory, because the model or Ollama runtime may not fully support that specific variant.
