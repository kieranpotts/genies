= Usage

Make sure the "run" scripts are executable:

[source,bash]
----
chmod +x ./run/*
----

[NOTE]
====
If Ollama is already running on your host machine (eg. installed via package manager or running as a service), stop it first to avoid port conflicts on 11434: `sudo systemctl stop ollama` (Linux).
====
[NOTE]
====
Larger models (eg. 33b parameter models) require significant memory. The Docker container is configured with a 32GB memory limit. If you plan to use models that require more memory, you may need to adjust the `mem_limit` setting in `docker-compose.yml`.

If you are using `docker compose up` outside swarm mode, `deploy.resources` is ignored. Set the compose file version to `2.4` and use `mem_limit`/`mem_reservation` so Docker applies the container memory limits correctly.

If the container still reports only ~8GB available, the Docker engine or VM itself is likely capped at that amount. Increase the Docker daemon / Docker Desktop memory allocation, or run Ollama on a host with the full machine RAM available.

If you are running on Docker Desktop, also verify the engine memory setting in Docker Desktop's Resources configuration.
====

== Docker memory configuration

If your host has more RAM than the container reports, Docker itself may be limiting memory. Adjust the engine memory allocation first, then restart the Ollama container.

* Docker Desktop: open Settings > Resources > Memory and raise the limit.
* WSL2: open the `.wslconfig` file in your Windows user directory and set a higher `memory=` value, then restart WSL.
* Linux Docker daemon: make sure the host has enough free RAM and that no cgroup limit is restricting the service.

Confirm the container-facing memory limit with:

[source,bash]
----
docker exec ollama free -h
----

If that command still reports only ~8GB, the Docker engine is the bottleneck.

Start the Ollama service in a Docker container:

[source,bash]
----
./run/start
----

Stop it:

[source,bash]
----
./run/stop
----

To stop the container and remove all persisted data (models, configurations, etc.):

[source,bash]
----
./run/cleanup
----

Use `./run/ollama` to interact with Ollama inside the container. All arguments are passed verbatim to the `ollama` program, which runs in the container.

To pull a model:

[source,bash]
----
./run/ollama run <model-name>
----

Example:

[source,bash]
----
./run/ollama run llama3.3
----

See the documentation on link:./models.adoc[models] to learn about your choices.

List all the models you have installed:

[source,bash]
----
./run/ollama ls
----

To run a model:

[source,bash]
----
./run/ollama run llama3.3
----

This command starts Ollama's built-in chat interface, from where you interact with the model via a command line interface. It is a minimal interface, and by default the models do not have access to your filesystem or other external systems.

To do more with your models, like to use them as coding assistants, you will need a front-end. For example, to use your models as coding assistants, you will need to install a coding agent and configure your local model as the agent's back-end. See the documentation on link:./front-ends.adoc[front-ends] for further information.

More CLI commands are available for Ollama - see https://docs.ollama.com/cli. You can also use https://docs.ollama.com/api/introduction[the API], served from `http://localhost:11434`, to integrate with Ollama programmatically from your own applications.
