= Security

Local model hosting brings convenience, but it also introduces new security considerations. The recommendations below are intended for users running Ollama or similar tools on a personal machine or in a small self-hosted environment.

== Run in containers

Containers provide a useful isolation boundary for model runtimes and downloaded model data. Running Ollama in Docker helps keep model files, runtime processes, and network bindings separate from the rest of the host system.

* Use the provided `docker-compose.yml` and `./run/start` script to keep the service contained.
* Persist data in a named volume rather than a host directory when possible.
* Keep the service running only when you need it.

== Network exposure

By default, Ollama listens on `localhost` only. Do not expose the service to the public internet unless you have explicitly configured a secure gateway and access controls.

* Avoid publishing port `11434` on a public interface.
* If you need remote access, use an SSH tunnel or a secure VPN rather than exposing the container directly.

== Resource isolation

Large models can consume a lot of memory and CPU. Container limits help prevent the Ollama runtime from affecting other services on the host.

* Configure `mem_limit` and `mem_reservation` in `docker-compose.yml`.
* Monitor host memory and CPU usage while loading large models.
* If the container is throttled by Docker engine limits, adjust the engine's memory settings rather than removing the container limits.

== Model files and trust

Models are code and data. Only download and run models from sources you trust.

* Use official or well-known model repositories.
* Do not use an Ollama instance running untrusted models to process sensitive data.
* If you need to test a new model, use a separate container or isolated environment.

== Access controls

Limit who can access the local Ollama service.

* Prefer binding to `127.0.0.1` (loopback only) when the service is only needed from the local machine.
* If LAN access is required, binding to `0.0.0.0` is necessary but must be protected with a local firewall rule.
* Do not run Ollama as root unless absolutely necessary.
* Protect any machine that hosts the service with current security updates and a strong local account password.

== Practical advice

* Treat the local Ollama service like any other networked tool: do not leave it open to untrusted clients.
* If you are unsure about a model or environment, start with a smaller model and confirm the runtime is stable before moving to larger ones.
